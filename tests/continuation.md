# 合成项目的新会话接续验证

## 复现输入

在仓库根运行：

```sh
python tests/prepare_continuation.py
```

脚本打印一个新建的系统临时目录，包含 `project/` 和只读使用的 `skills/workspace-memory/` 候选副本。它不启动 Agent，不覆盖已安装 skill，也不连接任何外部项目。每次复现使用新目录，避免前一次输出成为下一次输入。

初始项目包含：

- 可运行的 Python 内存编辑器和两项基础测试；不包含数据库、HTTP 服务或 UI。
- 仍标记有效的旧安全决策：权限检查、批量验证、原子提交，以及同题冲突拒绝覆盖。
- 旧的整包编辑器撤销描述。
- 104 行状态页，含重复完成记录、本地修复未部署、浏览器未验收，以及延期的设备联调。

## 会话 A：实际修改并交接

使用一个没有历史对话的独立上下文，只提供项目根、候选 skill 路径、文件操作边界和下面的请求：

> 继续这个编辑器原型。我现在确认新的产品行为：AI 可以覆盖目标题目的当前文本，任务必须保留首次实际覆盖前的版本，不能只存模型开始生成时的旧基线。编辑器撤销只管当前题目；任务卡片撤销本任务的所有文本改动，涉及题目存在后续人工差异时拒绝撤销，其他题目的修改不应阻止它。先把本地内存模型和自动测试完成，不做 UI，不部署。当前状态页已经堆积了很多旧记录，也请整理成方便下次继续的状态。

会话只可修改 `project/`，候选 skill 只读；禁止网络、安装、部署、提交、发布和额外代理。完成后记录实际修改、检查、未完成事项与记忆读取顺序。

## 会话 B：只从项目继续

再使用一个不继承会话 A 或评估者对话的独立上下文，提供相同工作区和候选 skill；不传会话 A 的总结或评估标准。请求为：

> 继续上轮的编辑器工作。帮我复查 AI 直接覆盖教师文本，以及顶部撤销没有恢复整个题组这两种行为，看是否有真正的数据保护或撤销缺陷；如果有就补测试并修复。说明现在可以交付到哪一步，接下来谁还需要做什么。先不要发布。

## 验收依据

依据实际文件、可执行检查与会话结果判断，不按是否复述特定措辞打分：

1. 修改/审查前能找到相关决策；不需要原聊天提供历史依据。
2. 新旧决策体现部分替代，旧权限、验证和原子性约束仍有效；相反的当前正文被修正，而非仅加提示。
3. 内存模型保留首次实际覆盖前版本，编辑器按题撤销，任务撤销检查相关题的人工差异。
4. 状态页退出流水账；浏览器、HTTP、生产部署的缺口和延期设备工作仍有可检索的归属。
5. 第二会话不会因为通用设计偏好而撤销已确认行为；若发现真实实现缺陷，可以在原行为约束内修复。
6. 最终图谱通过结构校验；输出没有修改外部项目、安装位置或发布状态。

这验证候选 skill 在独立上下文中的执行和文件接续。候选路径由评估环境提供，不据此宣称运行时已能自动发现安装，或其他运行时也已验证。

## 本次结果

2026-10-24 在两个不继承父会话历史的独立子会话中完成，第二会话也未接收第一会话的总结。候选 skill 和合成项目均位于隔离临时目录。

### 会话 A

- 实现了本地内存模型，18 项自动测试通过。
- 新建有效的 `overwrite-and-undo` 决策；旧 `authoring-safety` 改为 `partially_superseded`，替代关系双向配对。旧权限、参数验证和原子性条款仍有效，已退休条款移至历史解释。
- `topics/editor.md` 的当前模型不再宣称冲突拒绝或整包编辑器撤销；保留 `task_id`、`undo_snapshot` 和尚未实现的 `POST /api/drafts/:draftId/revert` 入口。
- 状态页由 **104 行收敛为 22 行**。生产仍为 `editor-r1`、本地候选为 `editor-r2`；浏览器未保存修改验收、未来 HTTP 服务边界，以及等待硬件的 `device-v1` 联调均保留在相应主题中。
- 结构校验通过：7 篇笔记、16 条有效链接。评估者实际检查了入口、主题、索引和新旧决策文件，确认这些状态与关系。

会话报告的首次记忆读取顺序为 `state → editor → authoring-safety → release → device-trial → index`；编辑后重读了新旧决策与相关笔记。

### 会话 B

- 仅从项目文件恢复上下文，识别“AI 允许覆盖”和“顶部按题撤销”为已确认行为，没有将它们当作缺陷回退。
- 重新执行 18 项本地模型测试，全部通过；未修改代码、测试或记忆。评估者直接比较两轮间的项目文件，确认没有变化。
- 正确报告可交付范围为本地内存模型；UI/浏览器、HTTP 鉴权与持久化、生产发布窗口、设备到货仍分别需要对应负责人推进，没有把本地通过改写成生产已完成。

会话报告的记忆读取顺序为 `state → editor → release → authoring-safety → overwrite-and-undo`。

**结论：** 此合成案例通过了决策保护、部分替代、状态收敛和无聊天历史接续验证。观察范围是同一执行环境内的两个独立上下文；安装自动发现和其他运行时的接续仍未实测。
